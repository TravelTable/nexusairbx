## Blocking decisions and unknowns

1. **Commercial authority:** repository parity proves two JSON files match, not that deployed Stripe objects, flags, trials, Team availability, taxes, currencies, cancellation rules, and usage reset behaviour agree. Billing operations must supply read-only production/staging evidence.
2. **Desktop Workspace role:** product and engineering must choose its destination before Connector navigation/content is changed. Existing persistence, migration and adapter work cannot be deleted as cosmetic cleanup.
3. **Backend production target and compatibility:** Nixpacks and internal documentation imply Railway, but exact environments, deployment order, feature flags, and rollback ownership are not encoded in the root repository.
4. **Missing state fixtures:** several trust-critical states can only be captured safely after deterministic fixtures exist. Live write or billing failure simulation is not an acceptable screenshot technique.
5. **Red baseline:** failures may be coupled (many agent-v2 failures share one harness/root cause), but that must be demonstrated, not assumed.
